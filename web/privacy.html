Privacy policy

Last updated 27 November 2026 · Version 3.0.1 · Academic project, not a commercial service.

Pinpoint is a privacy-first location-sharing project. This page explains what the Android app and the web client at the same host collect, why, and how to remove it. The short version: no advertising, no trackers, no third-party analytics, no data sales, and no friend-visible location history.

What we do not do

  • No advertising, profiling, third-party analytics or data sales.
  • No friend-visible location history: the server stores the latest publish plus a private trail that only you can read. The trail is pruned hourly after 7 days.
  • No IP-based geolocation, WebRTC location, or tracking IP addresses for analytics. Abuse limits use a short-lived keyed hash of the client address; raw IP addresses are not stored.
  • No friend list, account data or trail sent to OpenStreetMap. Your searches, map tiles and the route endpoints you choose reach the OSM services.
  • No hidden requests. The only automatic external request is at most one GitHub releases check a day for the same app version, plus one after installing a new version. It sends only Pinpoint/<version> as the User-Agent. GitHub sees the request IP, as with any HTTPS request. You can turn it off in Profile & settings.

Location sharing and consent

A friendship alone grants no visibility. You create a directional share naming one recipient, a precision level and an optional expiry. The server re-checks the permission on every read. Pause, revoke or expiry takes effect immediately; there is no grace period or cache. Location is latest-only.

Transport, storage and devices

Location updates travel over HTTPS. The backend stores the latest location record per user so it can deliver an active share, plus a private trail that only the owner can read; there is no friend-visible location history. In the current hosted build the backend can read the latest coordinates to enforce precision and consent — server-delivered locations are not end-to-end encrypted. Messages between friends are different: the client encrypts them with X25519, HKDF-SHA256 and AES-256-GCM, and the server stores only ciphertext, public keys and read state. The app keeps its local encryption keys in the device keychain. The app lock PIN is stored only as an Argon2id hash on the device; biometrics never leave the device. Signing out or deleting the account removes the local session and the local keys.

Diagnostics and crash reports

A crash report is sent only when you press Send report. It contains the error name, message and a short stack, with URLs and token/password-like fields redacted. It never contains your location, IP address, email, session cookie, CSRF token or a device identifier. The manual Help & diagnostics form sends only the category and the message you type.

Your rights and choices

  • Access / export: your profile and current sharing state are visible in the app; open a GitHub issue for a machine-readable export.
  • Rectification: edit your display name in Profile & settings or the web Account panel.
  • Erasure: delete your account in Profile & settings → Danger zone, or the web Account → Delete account. This immediately removes your profile, friendships, shares, current location, private trail, notes, check-ins, emergencies, encrypted messages, message keys and sessions.
  • Objection / withdrawal: revoke a share or turn off the update check at any time.

Contact

This is an academic project. For privacy questions, data export or a deletion request, open an issue at github.com/Prince-of-Nothing/Pinpoint/issues.

OpenStreetMap

Map data is © OpenStreetMap contributors, available under the Open Database License. Pinpoint does not use the public OSM tile server; it uses a self-hosted tile proxy or a configured provider.
